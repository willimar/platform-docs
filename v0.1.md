# Handoff — Agent Platform v0.1

## O projeto

Plataforma genérica de execução de agentes (YAML declarativo + loop LLM + 
ferramentas @tool). Multi-repo no GitHub, dev local via uv workspace.
Motor genérico que executa qualquer agente declarativo sem mudanças no core.

## Dev local (F:\ai-platform)

- `pyproject` raiz com `[tool.uv.workspace]` (members: os 6 pacotes)
- `setup.ps1` clona irmãos e injeta nos consumidores:
  ```toml
  [tool.uv.sources]
  agent-sdk = { workspace = true }
  ```

- `git update-index --assume-unchanged pyproject.toml` (platform-core e agentes)
- `new-agent.ps1` cria esqueleto completo de novo agente em um comando

## Próximos passos (v0.2 — .NET 10 + microserviços)

### Arquitetura alvo
- Reescrita do motor em **.NET 10** com arquitetura **hexagonal** (ports/adapters)
- **Microserviços** isolados orquestrados via Docker Compose (local-first na v0.2, AWS na v0.3)
- **3 NuGet packages**: `Contracts` (público, semântico), `Core`, `Adapters`
- **YARP.ReverseProxy** como gateway
- **MongoDB Atlas** (free M0) para config de agentes
- **Redis** para sessões de conversa (TTL nativo)

### Serviços planejados
1. YARP Gateway (port 5000) — roteamento, auth, rate limiting
2. Agent Registry Service (port 5002) — CRUD + SQLite→Mongo
3. Agent Executor Service (port 5001) — invoca workers via Docker
4. Agent Workers (containers isolados por agente)
5. Platform Admin Service (port 5003) — dashboard Blazor (opcional)

### Novas capacidades em v0.2
- **Sessões conversacionais** com persistência (Redis + TTL)
- Suporte a agentes stateful (ex: suporte técnico multi-turno)
- Tools built-in `sessao_salvar`/`sessao_ler` injetadas pela plataforma
- Deploy via GitHub Actions → Docker images → Docker Compose
